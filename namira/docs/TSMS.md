# اتصال ارسال پیامک TSMS
فقط ارسال پیاده شده؛ دریافت، اعتبار و گزارش تحویل به پروژه اضافه نشده‌اند.
آدرس و پارامترها از Python کاربر: http://tsms.ir/url/tsmshttp.php با GET و from,to,username,password,message.
هیچ نام پارامتر یا مسیر جایگزین حدس زده نشده است. ارسال واقعی HTTP بدون TLS مسدود است؛ برای فعال‌سازی باید HTTPS همین مسیر توسط TSMS تأیید شود. گواهی TLS بررسی می‌شود و redirect یا fallback به HTTP وجود ندارد.
## تنظیم خصوصی
کلیدها در تنظیمات خصوصی هاست خارج از هر دو docroot قرار می‌گیرند: _namira_live/.env یا فایل موجود config.local.json؛ کلیدهای تکراری در .env بر JSON اولویت دارند. مقادیر محرمانه وارد کد یا فایل عمومی نشوند.
SMS_DRIVER=tsms
SMS_ENABLED=1
TSMS_USERNAME=نام کاربری
TSMS_PASSWORD=رمز وب‌سرویس
TSMS_SENDER=خط مجاز ارسال
TSMS_API_URL=نسخه HTTPS تأییدشده همان نشانی نمونه
TSMS_HTTPS_CONFIRMED=1
OTP_SECRET=کلید تصادفی سروری حداقل ۳۲ نویسه
TSMS_RESPONSE_MODE=numeric_ids یا exact
TSMS_SUCCESS_VALUE=فقط در حالت exact، متن دقیق پاسخ موفق تأییدشده
PHP cURL و mbstring لازم‌اند و هاست باید اتصال خروجی HTTPS به TSMS را اجازه دهد.
نمونه Python تعریف پاسخ موفق را ندارد. numeric_ids فقط پس از تأیید اینکه پاسخ موفق حساب شناسه عددی بالاتر از کدهای خطای نمونه است فعال شود؛ این قالب در تست‌ها ساختگی است و تأیید واقعی TSMS ادعا نمی‌شود. در حالت exact پاسخ موفق باید دقیقاً تأیید شود. پاسخ خالی، ناشناخته یا خطا OTP را فعال نمی‌کند.
در بسته، SMS_DRIVER=disabled و SMS_ENABLED=0 باقی می‌مانند. تنها پس از تنظیم کلیدها و اجازه آزمون واقعی فعال شود.
## اتصال
MemberWeb از همان MobileAuth::request استفاده می‌کند؛ درایور پیش‌فرض اکنون SmsService است. صحت OTP، انقضا، هش، تلاش ناموفق و بازیابی/ثبت‌نام همان ساختار موجود را دارند.
برای اعلان آینده فقط کد سمت سرور مجاز: (new SmsService($db))->notify($mobile,$text,'order:125:shipped:v1').
فعلاً هیچ پیامک سفارش یا درخواست طراحی خودکار متصل نشده است.
## محدودیت و خطا
کد ۶رقمی، اعتبار دو دقیقه، فاصله ارسال ۶۰ثانیه و سقف ۵ درخواست OTP هر شماره در ساعت از همه IPها. سقف عمومی ارسال ۱۰۰ در ساعت و هر گیرنده ۱۰ در ساعت قابل تنظیم است.
شناسه رویداد باید برای یک پیام منطقی ثابت باشد. رویدادهای تکراری تا ۷روز با rate_limits موجود حذف می‌شوند؛ false یعنی قبلاً رزرو شده است. برای رویداد جدید، شناسه جدید بدهید. پس از timeout یا پاسخ نامشخص، تکرار خودکار انجام نمی‌شود؛ برای ارسال مجدد آگاهانه شناسه جدید لازم است.
متن/کد OTP، رمز، URL حاوی رمز یا پاسخ خام در log نوشته نمی‌شود. خطا برای کاربر عمومی است. دیتابیس جدید یا migration لازم نیست؛ هیچ رکورد محتوایی تغییر نمی‌کند.
