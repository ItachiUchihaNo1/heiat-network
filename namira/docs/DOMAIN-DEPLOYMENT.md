# استقرار naamiraa.ir و پنل مستقل

دو ریشه وب وجود دارد: public_html برای naamiraa.ir و admin.naamiraa.ir برای پنل. کد، تنظیمات و مخزن فایل مشترک در _namira_live بیرون از هر دو document root نگه‌داری می‌شوند. index هر ریشه سطح دسترسی خود را با ثابت NAMIRA_SURFACE تعیین می‌کند؛ مقدار آن از پارامتر درخواست یا Host استخراج نمی‌شود.

تنظیمات مشترک:

APP_URL=https://naamiraa.ir
PUBLIC_APP_URL=https://naamiraa.ir
ADMIN_APP_URL=https://admin.naamiraa.ir
APP_ENV=production

ورود مدیر از admin.naamiraa.ir انجام می‌شود. مشتریان و ارسال‌کنندگان از سایت عمومی استفاده می‌کنند. کوکی‌ها host-only و با نام و برچسب نشست جدا هستند. هیچ دامنهٔ مشترک کوکی مانند .naamiraa.ir تعریف نمی‌شود. عملیات مدیریت روی ریشه عمومی پیش از CSRF/تغییر دیتابیس رد می‌شوند؛ کنترل نقش و CSRF پنل همچنان لازم است. GET قدیمی پنل به دامنه مدیر می‌رود؛ POST میان دو دامنه منتقل نمی‌شود. فایل و سفارش خصوصی در محیط مدیریت، همان نشست مدیر را حفظ می‌کنند.

برای انتقال داده، MySQL مستقل و کاربر محدود به همان دیتابیس با cPanel ساخته می‌شود. مشخصات FTP مجوز ساخت دیتابیس نیست. رمز فقط از Secret استقرار خوانده می‌شود و در GitHub source یا گزارش چاپ نمی‌شود. رمز نصب یک‌بارمصرف فقط در پوشه خصوصی است. نصب کپی تنها با کلید خصوصی، نشست مجاز، CSRF، مبدأ خصوصی از پیش تنظیم‌شده و دیتابیس مقصد کاملاً خالی اجرا می‌شود. پشتیبان SQL و گزارش شمارش پیش از کپی ساخته می‌شود؛ حساب‌های مدیر و اصل فایل‌ها حفظ می‌شوند. مهاجرت‌های لازم فقط روی دیتابیس کپی‌شده اجرا می‌شوند. مبدأ حذف یا بازنویسی نمی‌شود. پس از موفقیت، کلید مصرف و نصب قفل می‌شود.

فایل .migration-source.json داخل _namira_live تنها مسیر خصوصی مبدأ را در کلید root نگه می‌دارد. این مسیر از ورودی وب پذیرفته نمی‌شود. نمونه مبدأ تأییدشده این حساب /home/ouidoyhy/Public_html/new/_namira است. این تنظیم باید فقط در مرحله استقرار و پس از بررسی مالکیت مبدأ نوشته شود.

آزمون‌ها:

php tests/domain-routing.php public
php tests/domain-routing.php admin
php tests/domain-migration.php
CALLS_UI_MANIFEST=storage/calls-ui-fixture.json php tests/calls.php
python3 tests/domain-http.py

آزمون HTTP فقط روی دو سرور localhost با دیتابیس fixture ایزوله اجرا می‌شود. بررسی TLS واقعی، ورود مدیر روی دامنه زنده، محافظت داده خصوصی و تطبیق document root باید در استقرار جداگانه تأیید شود.
