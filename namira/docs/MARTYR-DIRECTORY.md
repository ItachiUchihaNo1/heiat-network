# صفحه شهدا
نشانی عمومی: /index.php?page=martyrs
- تنها پرونده‌های منتشرشده، حتی پرونده بدون تصویر، با صفحه‌بندی ۲۴تایی نمایش داده می‌شوند.
- کارت مشترک views/martyr-card.php در خانه و فهرست استفاده می‌شود: تصویر، نام، شهر سکونت و موضوعات عمومی، مشاهده پروفایل موجود.
- تصویر شاخص از رابطه موجود media_public_martyrs.is_featured خوانده می‌شود؛ اگر تصویر شاخص مخفی باشد، تصویر مرتبط عمومی بعدی جایگزین می‌شود و اگر تصویری نباشد، نشان نامیرا دیده می‌شود.
- در پنل تصاویر و آثار، اثر را ویرایش کنید؛ از «تصویر شاخص برای پرونده» شهید مرتبط را انتخاب و ذخیره کنید. انتشار مستقیم مدیریت موجود حفظ است. شاخص سایر پرونده‌های مرتبط با اثر حفظ می‌شود.
- جست‌وجو و فیلترها همان کامپوننت و الگوی گالری را دارند؛ endpoint مجزای martyrs-data نتیجه و گزینه‌ها را از پرونده‌های عمومی حساب می‌کند. ترکیب محورهای مختلف AND، مقادیر یک محور OR، و جغرافیا وابسته به نقش و والد است.
- لینک مشاهده همه شهدای خانه به فهرست جدید است. لینک دلخواهی که مدیر صریحاً برای یک بلوک تنظیم کرده، حفظ می‌شود.
- گزینه شهدا در کشوی همبرگری موبایل است. نوار پنج‌گزینه‌ای پایین تغییر نمی‌کند.
- جدول/ستون جدید یا مهاجرت لازم نیست. روابط و محتوای واقعی در استقرار دستکاری نمی‌شوند.
## اجرا و آزمون
راه‌اندازی مطابق README فعلی PHP و پایگاه داده است.
php tests/martyr-directory.php
این آزمون یک دیتابیس مستقل SQLite می‌سازد. برای MySQL فقط دیتابیس namira_test_showcase پذیرفته می‌شود؛ TEST_SHOWCASE_DB_DSN و TEST_DB_USER و TEST_DB_PASSWORD را در محیط آزمون تعیین کنید.
برای مرورگر پس از آزمون بالا: PLAYWRIGHT_MODULE را به Playwright نصب‌شده متصل و node tests/martyr-directory-ui.cjs اجرا کنید. HTTP فقط با router محافظت‌شده آزمایشی آغاز می‌شود؛ هیچ مسیر تستی استقرار نمی‌یابد.
## بازگشت
فایل‌های قبلی در _namira_live/backups/martyr-directory-<source12> قبل از جایگزینی ذخیره می‌شوند. برای بازگشت، فایل‌های دارای oldHash در manifest را از همان پوشه به مسیر قبلی برگردانید؛ فایل‌های جدید می‌توانند بلااستفاده باقی بمانند. برای assetها نسخه پشتیبان در مسیر public/assets ذخیره شده و باید به هر دو docroot منتقل شود. داده‌ها و تصاویر را حذف نکنید.
