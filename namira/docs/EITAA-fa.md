# اتصال وب‌اپ نامیرا به ایتا
نامیرا همان پروژه PHP، همان کاربران، تصاویر، فروشگاه و دیتابیس فعال را استفاده می‌کند؛ هیچ بانک محتوای جدا یا پنل تازه‌ای ایجاد نشده است.

## تنظیم لازم
به شیء اصلی فایل خصوصی /var/www/naamiraa/_namira_live/config.local.json این بخش را اضافه کنید؛ سایر مقادیر دیتابیس، پیامک و بله حفظ شوند:
```json
"eitaa": {
  "enabled": true,
  "token": "توکن برنامه ثبت‌شده در ایتا"
}
```
این قطعه مستقل یک فایل JSON کامل نیست؛ ویرگول بین اعضای شیء اصلی را رعایت کنید. توکن واقعی در GitHub، فایل عمومی یا HTML قرار نمی‌گیرد. آدرس API در کد دقیقاً از مستند رسمی گرفته شده؛ نشانی یا پارامتر اضافه‌ای لازم نیست.

پس از تنظیم، مدیر اصلی یک بار پنل فعلی را باز کند تا migration افزایشی 014_eitaa همراه با پشتیبان اجرا شود. کاربران عمومی اجازه اجرای DDL ندارند. بدون این مرحله ورود ایتا پیام راهنمای مدیر می‌دهد.

آدرس تارنمای برنامک را روی https://naamiraa.ir/eitaa تنظیم کنید (بدون اسلش پایانی و بدون ریدایرکت). صفحات معمولی سایت هم در صورت حضور initData اتصال را تشخیص می‌دهند. در حالت disabled سایت قبلی برقرار است.

## حساب و داده‌ها
جدول eitaa_accounts فقط شناسه ایتا، user_id همان جدول users و وضعیت پیام خوش‌آمدگویی را نگه می‌دارد. برای کاربر تازه، حساب عضو عادی در users ساخته می‌شود؛ نام/شماره مشابه باعث تصاحب یا ادغام حساب دیگری نمی‌شود. اگر کاربر در سایت وارد حساب موجود باشد، اتصال شناسه ایتا به همان حساب فقط پس از تأیید صریح انجام می‌شود. نگاشت موجود تغییر یا بازنویسی نمی‌شود. ورود مدیران و سطح دسترسی آن‌ها از مسیر ایتا پذیرفته نمی‌شود.

امضای initData در PHP با HMAC-SHA256 و hash_equals، زمان اعتبار حداکثر ۵ دقیقه و جلوگیری از تکرار همان proof در نشست دیگر بررسی می‌شود. اطلاعات خام initData و توکن به مرورگر بازگردانده یا در دیتابیس/لاگ ذخیره نمی‌شوند. CSRF و محدودیت تعداد درخواست برقرارند. سرویس ارسال عمومی قابل فراخوانی از مرورگر برای متن یا گیرنده دلخواه وجود ندارد.

ورود پیامکی، تأیید شماره برای خدمات فعلی و ضوابط حساب موجود حذف نشده‌اند. ورود ایتا شماره موبایل را تأییدشده فرض نمی‌کند. پیاده‌سازی requestContact یا اعلان خودکار سفارش/طراحی جزو این اتصال اولیه نیست؛ این فرایندها فعلاً همان رفتار سایت را دارند و برای انتشار مرکز برنامک باید مسیرهای نیازمند شماره در ایتای واقعی بررسی شوند.

## پیام
پیام داخل ایتا است، نه SMS. API ثابت https://eitaayar.ir/api/app/sendMessage با POST JSON و token/chat_id/text استفاده می‌شود. تنها ok=true و result=success موفق محسوب می‌شود. TLS، timeout و اندازه پاسخ کنترل می‌شود؛ redirect/retry خودکار ندارد. تابع مرکزی EitaaApp::send برای استفاده سمت سرور موجود است؛ فعلاً به سفارش‌ها یا طراحی وصل نشده است.

بعد از ورود معتبر، اگر مجوز ارسال در داده امضاشده وجود داشته باشد، پیام خوش‌آمدگویی یک بار ارسال می‌شود؛ در غیر این صورت دکمه اختیاری درخواست اجازه نمایش داده می‌شود. وضعیت sending پیش از تماس ثبت می‌شود؛ نتیجه مبهم unknown است و به‌صورت خودکار دوباره ارسال نمی‌شود. قطع فرایند ممکن است وضعیت sending باقی بگذارد؛ بررسی دستی مدیر لازم است و برای جلوگیری از پیام تکراری retry خودکار ندارد.

## WebView و امنیت
SDK فقط هنگام فعال بودن اتصال در صفحات عمومی از https://developer.eitaa.com/eitaa-web-app.js بارگذاری می‌شود. مسیر اصلی/داخلی دکمه Back ایتا را مدیریت می‌کند. لینک خارجی با کلیک کاربر از openLink باز می‌شود. مسیر پرداخت بله برای نشست ایتا صفحه ادامه با دکمه خروج از WebView دارد؛ روند پرداخت عادی سایت حفظ شده است.

CSP صفحات عمومی فعال اجازه SDK رسمی و frame-ancestors فقط self و https://web.eitaa.com می‌دهد. هدر DENY در پنل حفظ شده است. نشست عمومی HTTPS در حالت فعال SameSite=None و Secure است؛ CSRF همچنان لازم است. مسدودی third-party cookies مرورگر می‌تواند ورود در iframe را محدود کند؛ پیام نشست نمایش داده می‌شود و حفاظت کوکی به روش ناامن دور زده نمی‌شود.

اگر Nginx بیرون PHP هدر X-Frame-Options یا CSP جدا اضافه کرده باشد، باید سیاست آن فقط برای سایت عمومی با این سیاست هماهنگ شود؛ تغییر خودکار در فایل‌های /etc/nginx انجام نشده و پنل مدیریت نباید قابل iframe شود.

## اعتبارسنجی
آزمون محلی با داده ساختگی و SDK شبیه‌سازی‌شده است؛ هیچ پیام واقعی یا پرداخت انجام نشده است. آزمون نهایی اندروید، دسکتاپ و وب ایتا با توکن واقعی بعد از تنظیم سرور لازم است. آماده بودن کد به معنی تأیید انتشار در مرکز برنامک‌ها نیست.
