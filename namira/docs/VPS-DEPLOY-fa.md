# استقرار نامیرا روی VPS

این روش فقط برای Ubuntu، PHP 8.3، Nginx و مسیرهای تأییدشده زیر است:

- سایت: `/var/www/naamiraa/public_html`
- مدیریت: `/var/www/naamiraa/admin.naamiraa.ir`
- هسته: `/var/www/naamiraa/_namira_live`
- دیتابیس موجود: `namira_app`
- پشتیبان پیش از انتقال: `/var/backups/naamiraa/deploy`

## راه‌اندازی یک‌باره

نصاب `deploy/install_vps.py` را از یک commit ثابت همین مخزن دریافت و بررسی کنید؛ سپس در نشست SSH مدیر سرور با sudo اجرا کنید. آرگومان‌های آن `--source-ref` (SHA کامل همان commit) و `--public-key` (کلید عمومی اختصاصی استقرار Ed25519) هستند. کلید خصوصی، گذرواژه دیتابیس و تنظیمات پیامک ورودی نصاب نیستند.

نصاب حساب بدون sudo به نام `namira-deploy` می‌سازد. کلید آن تنها دو فرمان `status` و `deploy <revision> <sha256>` را می‌پذیرد. ورود تعاملی، انتقال پورت و عامل SSH مجاز نیست. فایل فرمان و سیاست استقرار متعلق به root هستند. حساب `naamiraadmin` تغییر نمی‌کند. نصاب گروه خواندن کد را به سرویس وب اضافه و Nginx و PHP-FPM را به‌صورت graceful بازخوانی می‌کند؛ تنظیمات Nginx را ویرایش نمی‌کند.

قبل از اجرا، پشتیبان مستقل VPS و storage نگه دارید. نصاب از ورودی فعلی و پوشه‌های assets نسخه بازگشت نگه می‌دارد؛ هنگام شکست بررسی سلامت آن‌ها را برمی‌گرداند. اختلاف فایل‌های assets سایت و مدیریت، مسیرهای غیرمنتظره و تنظیمات سفارشی سرویس‌ها باعث توقف می‌شوند و باید بررسی شوند.

## تنظیم گیت‌هاب

در مخزن `ItachiUchihaNo1/heiat-network`، محیط `namira-production` را در Settings → Environments بسازید. پیش از ثبت کلید، Deployment branches را فقط به شاخه `namira-production` محدود کنید. در همین محیط دو Secret تعریف کنید:

- `VPS_DEPLOY_KEY`: کلید خصوصی اختصاصی استقرار، بدون passphrase؛ کلید شخصی مدیر را استفاده نکنید.
- `VPS_KNOWN_HOSTS`: کلید میزبان IP سرور که قبلاً با روش مطمئن تأیید شده است؛ از اعتماد خودکار به ssh-keyscan هنگام اجرا استفاده نکنید.

به توکن یا رمز دیتابیس در GitHub نیازی نیست. فایل `config.local.json` و storage روی سرور باقی می‌مانند. هر کس امکان تغییر کد شاخه تولید یا workflow و دسترسی به محیط تولید را داشته باشد، عملاً به اجرای کد برنامه دسترسی دارد؛ دسترسی شاخه و محیط را فقط به افراد مورد اعتماد بدهید.

## انتقال‌های بعدی

Workflow با عنوان `Namira VPS deployment` روی شاخه آماده‌سازی فقط آزمون و بسته‌بندی می‌کند. انتقال تنها برای شاخه `namira-production` و پس از موفقیت آزمون‌ها اجرا می‌شود. قبل از فعال‌کردن این شاخه، ورود محدود `status` را آزمایش کنید.

بسته شامل کد برنامه و assets است؛ config، فایل‌های آپلود، کلیدها و آزمون‌ها در بسته نیستند. سرور SHA256، مسیرها، نوع فایل، PHP lint، افزونه‌ها و نسخه schema را بررسی می‌کند. سپس نسخه SQL و شمارش رکوردهای دیتابیس گرفته می‌شود و اشاره‌گر نسخه با یک عملیات عوض می‌شود. بررسی HTTPS باید نسخه جدید را در سایت و مدیریت تأیید کند؛ در غیر این صورت کد به نسخه قبل برمی‌گردد.

این جریان migration اجرا نمی‌کند. schema عقب‌مانده باعث توقف می‌شود و باید جداگانه بررسی و ارتقا داده شود. بازگشت خودکار فقط مربوط به کد است؛ اطلاعات و فایل‌های کاربران بازنویسی نمی‌شوند. نسخه‌های قدیمی خودکار حذف نمی‌شوند. پشتیبان دیتابیس روی همین VPS جایگزین پشتیبان خارج سرور یا پشتیبان فایل‌ها نیست.

## آزمون‌ها

روی Linux: `python3 namira/tests/vps-deploy.py` و `php namira/tests/admin-managers.php` و `php namira/tests/short-links.php`.
آزمون‌های استقرار از پوشه‌های موقت و پاسخ‌های ساختگی سلامت استفاده می‌کنند؛ به سرور واقعی و پیامک یا پرداخت متصل نمی‌شوند. آزمون واقعی انتقال پس از نصب حساب و ثبت Secrets لازم است.
